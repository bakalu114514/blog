# Vue 学习笔记（五）：计算属性（computed）

**日期：2025.12.23**  
在前面已经学习了模板语法、事件处理以及数组响应式之后，今天开始接触 **计算属性（computed）**。计算属性是 Vue 中非常重要的一个概念，主要用于**处理模板中的复杂逻辑，并提升性能与可读性**。

---

## 一、为什么需要计算属性？

在模板中可以直接写 JavaScript 表达式，例如：

```html
<p>{{ classgroup.content.length > 0 ? 'Yes' : 'No' }}</p>
```

虽然这样是可行的，但当逻辑逐渐变复杂时：

- 模板会变得臃肿、难以阅读
- 同样的逻辑可能被多次使用
- 不利于后期维护

因此，Vue 提供了 **computed 计算属性**，用于将这些逻辑抽离到脚本中统一处理。

---

## 二、示例：使用计算属性简化模板逻辑

### 整理后的示例代码

```vue
<template>
  <h3>{{ classgroup.name }}</h3>
  <!-- <p>{{ classgroup.content.length > 0 ? 'Yes' : 'No' }}</p> -->
  <p>{{ classContent }}</p>
</template>

<script>
export default {
  data() {
    return {
      classgroup: {
        name: '小羊',
        content: ['前端', 'Java', 'Python']
      }
    }
  },
  // 计算属性
  computed: {
    classContent() {
      return this.classgroup.content.length > 0 ? 'Yes' : 'No'
    }
  }
}
</script>
```

### 代码说明

- `classContent` 是一个计算属性
- 它依赖于 `classgroup.content.length`
- 当 `content` 数组发生变化时，`classContent` 会自动重新计算
- 模板中只需像普通变量一样使用 `{{ classContent }}`

---

## 三、computed 与 methods 的核心区别（重点）

这是理解计算属性时**必须掌握的一点**。

### 1. computed 的特点

- **基于响应式依赖进行缓存**
- 只有当依赖的数据发生变化时，才会重新计算
- 多次访问，结果直接从缓存中读取

### 2. methods 的特点

- 不具备缓存机制
- 只要组件重新渲染，方法就会被重新调用
- 调用次数 = 访问次数

### 对比示例说明

假设：

- 页面中多次使用同一个结果
- 且依赖的数据没有发生变化

| 对比项 | computed | methods |
|----|----|----|
| 是否缓存结果 | 是 | 否 |
| 是否依赖响应式数据 | 是 | 是 |
| 多次调用开销 | 低 | 高 |
| 推荐使用场景 | 计算型数据 | 事件 / 动作逻辑 |

正如你在注释中提到的：

> 在计算条件不变的情况下，计算属性被访问 100 次，也只会计算 1 次；而方法会执行 100 次。

这也是为什么 **computed 更适合用于“结果型数据”**。

---

## 四、计算属性的典型使用场景（补充）

计算属性通常用于：

- 对已有数据进行加工、筛选、统计
- 根据多个响应式数据推导出一个新结果
- 替代模板中过于复杂的表达式

例如：

- 列表过滤
- 状态判断（是否为空、是否达标）
- 多字段组合显示

---

## 五、使用计算属性的好处总结

- 提升模板可读性，避免复杂逻辑直接写在模板中
- 提高性能，避免不必要的重复计算
- 代码结构更清晰，职责更明确
